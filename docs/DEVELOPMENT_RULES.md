# B2-1 개발 규칙

이 문서는 기존 기능과 공식 B2-1 요구사항을 유지하며 코드를 읽기 쉽게 정리하는 기준입니다.

1. 함수와 메서드 바로 위에는 역할을 요약한 한 줄 주석만 둡니다. 긴 설명은 `docs/`의 파일별 문서에 둡니다. 클래스와 상수에는 불필요한 장식 주석을 달지 않습니다.
2. 빈줄과 공백은 문법과 구분에 필요한 만큼만 씁니다. 함수 인자는 한 줄을 우선하고, 길어지면 자연스러운 단위로만 나눕니다.
3. 이름은 역할이 드러나게 짓고, 같은 변환·검증·저장 코드는 공통 함수로 모읍니다. 반복 할당은 보기 좋게 정렬할 수 있지만, 정렬만을 위한 과도한 공백은 피합니다.
4. import는 표준 라이브러리와 프로젝트 모듈을 구분해 정리합니다. 메서드 체인은 짧으면 한 줄로 두고, 길면 호출 단위로 나눕니다. 점(`.`)을 맞추려고 억지 공백을 넣지 않습니다.
5. `__main__.py`의 진입 함수에 사용자 정의 데코레이터를 한 번 적용합니다. 사용자에게 보이는 공통 오류 메시지와 종료 코드는 그 데코레이터에서 처리합니다. 일반 업무 함수의 `try/except`는 피합니다.
6. CSV 가져오기는 각 행을 먼저 검증하고, 잘못된 행은 건너뛰어 다음 행 처리를 계속합니다. 일반 업무 함수에서는 try/except를 사용하지 않고 공통 오류 처리는 진입점 데코레이터에서 처리합니다.
7. JSONL 세 파일 분리, 기본 카테고리 초기화, CLI 명령과 출력 의미, 거래 검증, 파일 재작성 방식, 표준 라이브러리만 사용, Python 3.10 이상 호환을 유지합니다.
8. 수정 후 `unittest`와 별도 임시 데이터 폴더의 주요 CLI 흐름을 확인합니다. 실제 `data/` 파일은 검증에 사용하지 않습니다.
