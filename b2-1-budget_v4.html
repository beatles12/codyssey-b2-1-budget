구조와 안전성 설명

파일명만 외우지 말고 “왜 책임을 나눴는지”를 설명합니다.

CLI

cli.py

쉬운 뜻: 접수창구.

터미널 명령을 해석하고 사용자 입력을 받으며 결과를 출력합니다.

argparse는 터미널 명령과 옵션을 읽어주는 Python 표준 도구입니다.

Service

service.py

쉬운 뜻: 업무 담당자.

날짜·금액 검증, 검색, 요약, 카테고리 규칙, 예산 계산을 담당합니다.

Repository

repository.py

쉬운 뜻: 서류 보관실.

JSONL 파일 경로와 실제 읽기·쓰기·임시파일 교체를 담당합니다.

30초 모듈 설명
“CLI는 사용자와 대화하는 역할만 맡고, Service는 검증과 업무 규칙을 맡으며, Repository는 실제 파일 저장을 담당합니다. 역할을 나누면 입력 방식이 바뀌어도 거래 규칙을 재사용할 수 있고, 저장 방식을 바꿔도 CLI 코드를 크게 바꾸지 않아도 됩니다.”
클래스 책임 경계 — TransactionService vs TransactionRepository
클래스담당하지 않는 일
TransactionService거래 검증, 최근 목록, 검색, 월 요약, 수정/삭제 규칙파일 open/json.dump를 직접 하지 않음
TransactionRepositorytransactions.jsonl 읽기/추가/찾기/재작성금액이 양수인지, 날짜가 맞는지 같은 업무 규칙은 판단하지 않음
클래스 책임 경계 — CategoryService vs CategoryRepository

CategoryService는 “사용 중이면 삭제 금지” 같은 규칙을 판단합니다. CategoryRepository는 categories.jsonl을 실제로 읽고 씁니다.

짧게 말하기
“Service가 삭제해도 되는지 판단하고, Repository가 실제 삭제를 수행합니다.”
update/delete 안전 처리 — 실제 코드 포인트
temp_path = self.file_path.with_suffix('.tmp') ... if found: temp_path.replace(self.file_path) return True

원본을 바로 중간 수정하지 않고 임시 파일을 완성한 뒤 교체합니다. 대상 ID가 없으면 임시 파일을 삭제하고 원본은 그대로 둡니다.

Python 핵심 개념 — 보여줄 코드 + 왜 썼나

정의만 말하지 말고 이 프로젝트에서 어떤 이득이 있는지 설명합니다.

Generator

yield

for line in file: ... yield Transaction(...)

쉬운 뜻: 한꺼번에 다 들고 오지 않고 하나씩 전달.

말하기
“iter_transactions()는 JSONL을 한 줄씩 읽어 거래를 yield합니다. list는 deque(maxlen)로 최근 N건만 유지합니다.”
Decorator

@safe_entry

@safe_entry def main() -> None: run_cli()

쉬운 뜻: 여러 방마다 경비원을 두지 않고 입구에 안전요원 한 명.

말하기
“공통 오류 처리를 진입점에 모아 중복 try/except를 줄였습니다.”
Type Hint

자료형 계약

def get_budget(self, month: str) -> int | None:

쉬운 뜻: 함수 입구와 출구에 붙인 표지판.

말하기
“실행을 강제하는 기능은 아니지만 사람이 이해하고 IDE가 오류를 찾기 쉽게 합니다.”
Generator 설명 주의: list는 deque(maxlen)로 최근 N건만 유지하지만, search는 최신순 출력을 위해 일치 결과를 deque에 모은 뒤 pop()으로 yield합니다. 따라서 search 결과가 매우 많으면 메모리가 증가할 수 있습니다.

JSONL vs CSV

JSONLCSV

조건 검색 때 JSONL 전체를 순회할 수 있습니다.

10만 건 · update/delete

한 건을 바꿔도 전체 JSONL을 다시 씁니다.

개선: DB의 ID 기반 UPDATE/DELETE.

CSV에 깨진 행이 섞였을 때 — 현재 전략과 다른 선택

전략뜻장점단점
현재: 부분 성공 + 리포트정상 행은 저장, 잘못된 행은 skipped좋은 데이터까지 버리지 않음사용자는 일부만 들어갔다는 사실을 알아야 함
전체 취소 / rollback한 행이라도 틀리면 전부 취소파일 전체 일관성이 중요할 때 안전정상 행도 모두 취소됨
사전 전체 검증 후 저장먼저 전 행 검사, 모두 정상일 때 저장all-or-nothing 구현 가능구조가 더 복잡해짐
현재 구현 설명
“이 프로그램은 부분 성공 방식을 선택했습니다. _prepare_import_row()에서 각 행을 먼저 검사하고, 잘못된 행은 저장하지 않고 skipped로 집계합니다. 정상 행은 기존 add_transaction()을 재사용해 저장하고, 마지막에 imported와 skipped 수를 보여줍니다. 전체 일관성이 더 중요한 환경이라면 먼저 전체 검증 후 하나라도 오류가 있으면 전부 취소하는 방식을 고려할 수 있습니다.”

초보자 용어 사전

단어에서 막히지 않도록.

argparse (아그파스)Python 표준 라이브러리. 터미널 명령과 옵션을 읽어서 정리해주는 도구. 예: summary, --month, --top을 구분.
CLICommand Line Interface. 마우스 버튼 대신 터미널 명령으로 프로그램과 대화하는 방식.
Service프로젝트에서 만든 업무 담당 계층. 검증·검색·요약·예산 같은 규칙 처리.
Repository저장소. 실제 파일을 읽고 쓰는 계층.
JSONL한 줄에 JSON 객체 하나를 저장하는 파일 형식.
Generatoryield를 이용해 데이터를 한꺼번에가 아니라 하나씩 전달하는 방식.
Decorator기존 함수를 감싸 공통 기능을 추가하는 Python 문법. 여기서는 safe_entry로 오류 처리.
Type Hint함수 입력·반환 자료형을 사람이 알기 쉽게 표시하는 표지판.
dataclass데이터를 담는 클래스를 간단히 만드는 Python 표준 기능. Transaction에 사용.
deque양쪽에서 빠르게 넣고 뺄 수 있는 Python 표준 자료구조. 최근 N건과 검색 결과에 사용.
UUID거의 겹치지 않는 고유 ID. 각 거래를 구별하기 위해 사용.
exit code프로그램이 끝났을 때 운영체제에 남기는 숫자. 정상은 0, 오류는 0이 아닌 값.
