핵심 개념 공부 카드

질문의 뜻부터 답변 주의점까지.

Generator / yield는 왜 썼나?▼
질문의 뜻
파일을 왜 한 번에 다 읽지 않았는가?
보여줄 코드
repository.py → iter_transactions()
for line in file: ... yield Transaction(...)
30초 답변
“Generator는 값을 한꺼번에 반환하지 않고 yield로 하나씩 전달합니다. JSONL을 한 줄씩 읽기 때문에 파일 전체를 한 번에 메모리에 올리지 않습니다. list는 deque(maxlen)를 함께 사용해 최근 N건만 유지합니다.”
주의: search는 파일 읽기는 스트리밍이지만 최신순 출력을 위해 일치 결과는 deque에 모읍니다.
Decorator / safe_entry는 왜 필요한가?▼
@safe_entry def main() -> None: run_cli()
30초 답변
“사용자에게 보여주는 공통 오류 처리를 진입점 한 곳으로 모았습니다. 그래서 여러 계층에 같은 try/except를 반복하지 않고, 오류가 나면 traceback 대신 원인과 해결 힌트를 같은 형식으로 보여줍니다. 오류 종료는 SystemExit(1)입니다.”
Type Hint는 실제로 무엇을 해주나?▼
def get_budget(self, month: str) -> int | None:
30초 답변
“month는 문자열이고 반환값은 정수 또는 None일 수 있다는 계약을 표시합니다. 실행 중 자동으로 강제하는 기능은 아니고, 사람이 코드를 이해하고 IDE가 실수를 찾기 쉽게 합니다.”
JSONL과 CSV를 왜 둘 다 쓰나?▼
JSONLCSV
역할내부 영구 저장외부 교환
tagslist 표현 쉬움쉼표 문자열 변환

“Transaction 구조와 tags 같은 리스트는 JSON과 잘 맞고, JSONL은 한 줄에 한 거래라 Generator와도 잘 맞습니다. CSV는 표 형태라 사람이 보기 쉽고 다른 프로그램과 교환하기 편해 import/export에 사용했습니다.”
update/delete가 왜 전체 파일을 다시 쓰나?▼
30초 답변
“JSONL 중간 한 줄을 안전하게 직접 덮어쓰기 어렵기 때문에 .tmp 파일을 새로 만들고, 성공하면 replace()로 원본과 교체합니다. 원본 중간 손상 위험을 줄이는 방식입니다.”
temp_path = self.file_path.with_suffix('.tmp') ... temp_path.replace(self.file_path)
10만 건이 되면 어디가 느려지나?▼
30초 답변
“검색은 JSONL 전체를 순회할 수 있고, search는 일치 결과를 deque에 모으므로 결과가 많으면 메모리가 늘어납니다. update/delete는 파일 전체를 재작성합니다. 데이터가 커지면 SQLite, 인덱스, pagination, ORDER BY/LIMIT으로 개선할 수 있습니다.”

말할 때 주의할 것

search는 완전한 상수 메모리가 아님.
파일은 한 줄씩 읽지만 일치 결과는 deque에 모음.
Type Hint는 런타임 강제가 아님.
계약 표시와 가독성/IDE 도움.
CSV import는 행 단위 try/except가 아님.
_prepare_import_row()에서 사전 검증 후 skipped 처리.
update는 대화형 방식.
update --id 실제ID 후 Enter면 기존 값 유지.
공식 미션이 모든 try/except를 데코레이터로 강제한 것은 아님.
현재 프로젝트가 중복을 줄이기 위해 safe_entry 중심으로 설계한 것.
사용 중 카테고리 삭제 금지.
TransactionRepository까지 확인해 무결성 보호.
마지막 10분 복습 순서: 전체 구조 30초 → add 흐름 → Generator → Decorator → update/delete 안전성 → JSONL vs CSV → 10만 건 한계 → 실제 명령 2~3개 시연.
