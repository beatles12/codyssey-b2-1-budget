3-1Generator · 한 건씩 읽는 흐름

무엇어떻게왜
필요할 때 다음 값을 내주는 Python 방식TransactionRepository.iter_transactions() -> Iterator[Transaction]가 파일의 각 줄을 읽어 yield Transaction(...) 실행파일 전체를 한 번에 list로 만들지 않고 순서대로 처리

list_transactions()는 deque(maxlen=limit)에 최근 N건만 남긴다. search_transactions()도 파일 읽기는 한 줄씩 하지만 최신 추가 순서의 역순 출력을 위해 일치 결과를 matches = deque()에 모두 모은다. 따라서 검색 결과 수만큼 메모리가 늘 수 있다. 여기서 최신순은 거래 날짜 정렬이 아니라 파일에 추가된 순서의 역순이다.

listsearch10만 건 병목

진행자 상세 노트
“Generator는 값을 필요할 때 하나씩 내주는 방식입니다. Repository의 yield 덕분에 파일을 줄별로 읽습니다. list는 출력 개수만 보관하지만 search는 순서를 뒤집으려고 일치 결과를 모으므로 검색 전체가 일정 메모리라는 뜻은 아닙니다.”

3-2Decorator · 공통 오류 처리 한 곳에

무엇어떻게왜
함수를 감싸 공통 동작을 붙이는 Python 문법__main__.py의 @safe_entry가 main()을 감싸고, decorators.py의 wrapper()가 대표 예외를 처리명령마다 같은 사용자 오류 문구와 종료 코드를 반복하지 않음
Service: raise ValueError→@safe_entry(main)→wrapper: except ValueError→힌트 출력→SystemExit(1)→$LASTEXITCODE 1

현재 데코레이터의 기능은 오류 처리다. CSV의 깨진 행을 skipped로 세는 일은 CsvService 내부에서 처리한다.

오류 시연입력·파일 오류

진행자 상세 노트
“Decorator는 함수 바깥에 공통 작업을 씌우는 문법입니다. 여기서는 main 앞의 @safe_entry가 오류를 받아 메시지와 힌트를 출력하고 실패 코드 1로 끝냅니다. 실행 로그를 기록하는 기능은 현재 구현에 없습니다.”

4-2거래 10만 건에서 느려지는 곳과 개선

list/search/summary는 조건에 따라 거래 파일 전체를 훑는다. list는 보관량만 N건으로 제한한다.
search는 일치 결과를 deque에 모으므로 일치 건수가 많으면 메모리도 늘어난다.
update/delete는 한 건 변경에도 거래 파일 전체를 새로 쓴다.
규모가 커지면 SQLite로 옮기고 ID, 날짜, 카테고리 등에 인덱스를 두며 결과를 페이지 단위로 조회한다.

인덱스는 책 뒤의 색인처럼 찾을 위치를 빠르게 좁히는 데이터베이스 구조다. SQLite와 인덱스는 현재 구현된 기능이 아니라 개선 방향이다.

읽기와 메모리전체 파일 재작성

진행자 상세 노트
“현재 JSONL은 간단하지만 10만 건이면 조회마다 전체 파일을 읽고, 수정·삭제도 전체 파일을 다시 쓰는 비용이 커집니다. SQLite의 인덱스로 ID·날짜·카테고리 검색을 빠르게 하고 페이지 조회를 도입할 수 있습니다. 실제 속도는 별도 측정이 필요합니다.”

4-3깨진 CSV 행: 부분 성공과 skipped

헤더·필수 열 검사→행별 날짜·종류·카테고리·금액 검사→정상: 저장 + imported / 오류: 건너뜀 + skipped

제공된 import_test.csv는 정상 1행과 숫자가 아닌 금액 1행이다. CsvService.import_transactions()는 행 안의 ValueError 등을 잡아 정상 행만 저장한다. 출력은 imported=1, skipped=1이다.

이 정책은 정상 데이터까지 버리지 않지만 일부만 저장된 상태가 된다. 현재는 전체 롤백이나 행 번호·원인별 리포트가 없다. 사용자는 두 건수를 확인하고 원본 CSV를 고쳐 재시도할 때 중복 저장에 주의해야 한다.

진행자 상세 노트
“현재 import는 부분 성공입니다. 한 행이 깨져도 정상 행은 저장하고 오류 행은 skipped로 셉니다. 결과 건수를 보여 주지만 어느 줄이 왜 실패했는지는 아직 출력하지 않습니다. 재시도하면 정상 행이 중복될 수 있어 원본과 건수를 대조해야 합니다.”
